# HK-T1 HKMA ART Principles Self-Assessment (Banks)

> **Verification required.** This is a working template, not a regulator-approved form. Principle numbers refer to the HKMA Supervisory Guidance for Responsible Adoption of Artificial Intelligence (Annex A to the HKMA circular of 15 October 2026), read on 25 October 2026. The questions summarise the guidance in this wiki's words; check the wording in the guidance itself. This is not legal advice.

<!-- -->

> **How to use:** This is a blank form. Copy it and fill in the empty cells for your institution. To copy it, follow the "Suggest an edit to this page" link in the footer to reach its Markdown source.

Rate each line Met, Partly met or Not met, record the evidence and name an owner for any gap. The principle-by-principle mapping to wiki controls is in the [Hong Kong Regulatory Crosswalk](03_Regulatory_Crosswalk.md#hkma-guidance-on-responsible-ai-adoption-principle-crosswalk).

## Accountability

| # | Principle | Question | Rating | Evidence | Gap owner |
|---|---|---|---|---|---|
| 1.1 | 1. Board and senior management | Has the board approved an AI strategy that sets out the approach to AI and the risk appetite? | | | |

| 1.3 | 1 | Does senior management review the strategy and framework regularly? | | | |
| 2.1 | 2. Use-case owners and human oversight | Does every deployed use case have a named owner who defines its authority and oversees its controls? | | | |

| 2.3 | 2 | Do reviewers have the competence, information, time and authority to challenge, override or stop the system, and is oversight effectiveness tested? | | | |

| 3.3 | 3 | Is AI that is not in the inventory restricted, and is shadow AI controlled? | | | |

## Resilience

| # | Principle | Question | Rating | Evidence | Gap owner |
|---|---|---|---|---|---|
| 4.1 | 4. Risk-commensurate management | Does a materiality and risk assessment decide the level of review and approval for each use case, and is it refreshed? | | | |
| 4.2 | 4 | Do material or higher-risk use cases get senior management sign-off, independent validation and, where appropriate, adversarial testing? | | | |
| 4.3 | 4 | Is each use case tested end to end against acceptance criteria before deployment and before material change, with residual risk accepted by the approver? | | | |
| 4.4 | 4 | Is monitoring tailored to the use case, including safeguards where AI monitors AI? | | | |
| 4.5 | 4 | Do material or higher-risk use cases have a built-in kill switch or equivalent, and credible fallback and recovery, including for third-party failure? | | | |
| 4.6 | 4 | Are records kept across the life cycle, and can material outputs be traced? | | | |
| 5.1 | 5. Risk management frameworks | Do contracts stop providers reusing personal or confidential data for training without authorisation, and is data masked where possible? | | | |
| 5.2 | 5 | Are AI providers subject to due diligence, contracts with audit rights and notifications, monitoring, and concentration and exit assessment? | | | |
| 5.3 | 5 | Are layered controls in place against data poisoning and prompt injection, beyond model instructions and filters? | | | |
| 6.1 | 6. Resources and expertise | Are resources and capacity planned, and are awareness and role-specific training in place? | | | |
